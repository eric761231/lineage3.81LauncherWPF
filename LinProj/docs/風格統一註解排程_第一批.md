# LinProj 風格統一／詳細註解排程（第一批）

範圍：`Encoder`、`LineageIme`、`ScreenSaverGuard`、`ConfigDatGen`、`DeployTool`、`EatPack`、`ReleasePackager`。

第三方／產生檔不進排程：`LineageIme\detours.h`、`detver.h`，`Encoder\GlobalUsings.cs`。  
C++ 的 `.h`＋`.cpp` 算 **1 個 class**（路徑兩筆都要改）。

共 **46** 個 class，**10 個一組**；第 5 組剩 6 個。

## 修改需求（每組開工必守）

開工某一組時，只動該組列出的檔案，並套用下列三條。做完再進下一組。

### 1. 補全大括號

檢查這些檔案中所有的 `if`、`else`、`for`、`foreach`、`while` 條件式與迴圈。若省略了 `{}`，**全部強制補上** `{}`，維持良好結構。單行也要加大括號。

### 2. 撰寫註解

為 **Class**、**Method**，以及關鍵邏輯區塊加上清晰的**繁體中文**註解。

- Class：檔頭或型別上方說明職責。
- Method：每個方法都寫（含 private／helper／轉換器），不要只寫主方法。C# 用 `///`；C++ 寫在函數前。
- 關鍵邏輯：分支、迴圈、協定／位元組處理等非一眼能懂的區塊補註解。
- 過繁、複述程式碼、過時的舊註解改寫成清楚短句，不要刪到變成沒說明。

### 3. 保持邏輯不變

**切勿**修改任何現有的執行邏輯、方法名稱或變數名稱。只動括號、換行與註解（以及為了加大括號而必需的排版）。

同一組內先補 `{}`，再補 Class／Method／關鍵區塊註解。

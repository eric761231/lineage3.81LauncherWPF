- 借位設計定案：**借用 `C_BroadcastToPledge`（opcode 75，血盟成員登入通知開關）**，不開新 opcode；沿用 `NumberingMarkerHook.cpp` 已驗證過的「用封包長度分支避免撞原生行為」手法。
- 落地的第一版：
  - 新建 `AutoPotionOverlay.cpp`/`.h`（Mimir 式 layered 自繪視窗，HOME 熱鍵開關），槽位輸入方式是**鍵盤打字輸入 itemId／skillId**（還沒有點擊背包道具的功能）。
  - 新建 `AutoPotionConfig.cpp`/`.h`：本機 cfg（`Core\auto_potion.cfg`，手刻 `key=value`）＋借位 opcode 75 的 54-byte 設定封包（治療/補魔各一個共用門檻＋5 槽）。
  - 伺服器：`C_BroadcastToPledge.java` 新增長包分支解析設定、`L1PcInstance` 加 `autoPotion*` 欄位、新建 `PotionTimer.java`（500ms tick，門檻判斷＋觸發喝藥，當時只處理 `kind=Item` 的槽）。
  - 舊版 `HelperDlg.cpp`（DMA 直接讀寫遊戲記憶體的舊輔助工具）整檔 `#if 0` 停用，不再繼續往這個方向擴充，改用後端判斷版取代。
  - `BroadcastToPledgeHook.cpp` 一度想把原生「血盟推薦」按鈕當新功能的觸發入口，後來發現底層 `Action_BrodcastToPledge` 登入時就會自動觸發（不只是點擊才觸發），導致 overlay 未經允許彈出，改成無害的 no-op，HOME/Insert 熱鍵才是正式入口。

- 目標：讓槽位可以直接拖拉背包道具進去，取代鍵盤打字輸入。
- 反組譯背包指標鏈（`InventoryDebugHook.cpp` 初版）：`*(DWORD*)0x009A9250` 背包基址 → `+0x2C` 物品數量 → `+0x58` 物品指標陣列；`BAGITEM_INFO` 結構 `{unknow1(vtable), id(實體objId), unknow2(點擊瞬間變動), name(Big5字串指標)}`，並實測證實 `id` 是**背包實體 objId**、不是道具樣板 id（同名道具 5 筆的 id 彼此不同但相近，是動態配置序號的特徵），因此樣板 id 決定改由**伺服器解析**（`pc.getInventory().getItem(objId)`），不在客戶端記憶體硬猜。
